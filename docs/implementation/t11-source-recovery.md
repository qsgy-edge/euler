# T11: source recovery and actual-used inspection (synthetic)

Issues: [#11](https://github.com/qsgy-edge/euler/issues/11), [#63](https://github.com/qsgy-edge/euler/issues/63). This slice uses only disposable SQLite and synthetic CLI archives. The current disposable schema is version 31; the original T11 receipts retain their version 18 identity. There is no production migration or live owner switch.

## Memory provenance in the Agent loop

The model's `source.expand` tool accepts exactly one of `eventId` (current session), `unitId` (published source), or `recordId` (canonical memory), plus a Unicode-code-point offset and a limit from 1 to 4096. A memory-search hit's `unitId` is a memory record identity; use its `record.recordId` with the `recordId` parameter to recover provenance. No model argument supplies a grant or raw filesystem path.

The memory path uses `retrieveMemorySource`: it requires the current active, verified, unconflicted and temporally valid head, intact source evidence, authorized scope and a target not excluded by its applicability conditions. A workspace record considers only member projects. An existing task grant supports bound or unbound cross-project reading and charges each actual recovery against its query/result/byte allowance. Qualification checks at freezing and dispatch do not charge another recovery. The source result carries the frozen memory snapshot into `usedMemories`, so a subsequent head change, forget, source failure or revoked grant blocks dispatch. Derived output copies reserve the original source grants in the existing `source-access` event before appending archive bytes, including lost acknowledgements and subsequent event expansion or session-search copies. Revocation still blocks these copies when the consuming run has no grant of its own. The owner-facing `source <recordId>` and historical `expandSource(recordId)` retain their existing inspection behavior.

After an actual `memory.search`, the Core attempts bounded recovery of the returned eligible records' exact provenance, once per record/head in that search. It does not perform another memory search or model call. Recovery results and explicit gaps are stored in the existing tool archive envelope's `sourceRecovery` field. The original `modelResult` remains the memory page. Retained tool batches from the current user turn supply recovery data throughout its complete ReAct loop in the P3 tail, marked as untrusted source data by the HTTP adapter; P2 tool history is unchanged. A new user input starts a new tail. If that optional tail would exceed the actual encoded request or run budget, it yields to the memory page, reporting a context-budget gap where it fits. Paging remains available through `source.expand`.

An unspecified request for an original quotation is not a locator. Without a precise record/event/unit identity or a retrieved provenance ref, the Agent must locate evidence through the existing source-search path; the Harness does not guess a source or scan ordinary memory before the first request. Automatic source recovery creates no durable memory, guidance, tool authority or additional persistent carrier. Backup, recovery and purge use the existing record/source/run dependencies and tool archive ownership.

## Source units and actual-used inspection

`ProbeStore.expandSource` verifies the complete archive acknowledgement and original text hash before returning a bounded Unicode-code-point page. `inspectAssembly` returns the frozen source acknowledgements and ordinals; derived source-unit or proposal expansion remains a separate unit lookup and cannot claim assembly membership from a matching raw acknowledgement alone. Direct unpublished raw-ref expansion is limited to its owning session; canonical memory provenance uses the separately scoped paths above. Derived cross-project outputs also require their recorded task grant; Agent source tools revalidate the current Host scope before returning those copies. `publishSourceUnit` registers a bounded, immutable source/archive range with its real source owner and target project; every project-visible publication requires a separate archived `user`-role decision bound to the originating active intent, source ref, exact range, kind and target project. Repeated publication reconciles by stable request identity. A source unit never changes the archive binding. Its target project can discover only the published range, not follow the returned locator to the mixed original. Reports/handoffs are pre-stored synthetic inputs here; their generation, delivery and export belong to T13.

`source_units` stores the source acknowledgement, target range, content hash and approval acknowledgement in typed columns; `payload` remains an immutable reconstruction envelope. Publication appends a `source_projection_jobs` row in the same transaction. A superseding publication must name a parent that has not already been superseded; this parent CAS is checked per lineage, so independent roots of the same project/kind remain separate lineages. Stale parents are rejected in the same transaction. Normal draining consumes pending jobs with generation/content-hash CAS; canonical read or indexing failure is durably marked `failed` and makes discovery unavailable until an explicit rebuild repairs it. Only an explicit project rebuild may repair a damaged projection, including `failed -> done` job recovery. Search and expansion expose unit-relative range metadata, so a mixed report does not disclose the original archive extent.

`searchSources` uses the existing external-content FTS with distinct `memory`, `session` and `proposal` owner kinds. The canonical owner is checked again on each hit and each expand; unpublished archive history is not scanned on ordinary search. Unprojected units, metadata mismatch or FTS damage return a dirty/unavailable coverage state, not an authoritative empty answer. `drainSourceProjection` is bounded and consumes only its durable source/proposal jobs; `rebuildSourceProjection` repairs the local project's source/proposal slice without dropping memory or other projects. Existing inert `evolution_proposals` are indexed by their owner and project scope; expansion restores the exact historical proposal payload/hash, never promotes a proposal to verified memory. Neither search nor expand activates guidance or tools.

Published-source cross-project reads reuse T10's task-bound grant, cumulative result/byte/query limits and revocation checks. A granted search/expand supplies a stable `queryId`: a content-free receipt records its request/result hashes and budget charge in the same transaction. Repeating that identity rechecks the current grant and immutable source, returns the same result without charging again, or reports `query-result-stale` if it cannot reconstruct the original result. Changing the request under the same ID fails. Local, ungranted reads do not create receipts. The synthetic Host must carry a stable operation ID through an unknown result; no model field can mint a grant or publication decision.

`ProbeSession.prepare(..., selected)` embeds eligible, current memory snapshots as untrusted data in the actual local-counting payload. The assembly ledger stores only source/memory refs, identities, hashes, order and reasons. `inspectAssembly` recovers the frozen selected memory event/revision and selected raw source refs, including after a later correction. An unselected record ID, duplicate selection, missing hash or lost selected source is an explicit gap. A not-dispatched assembly has frozen candidates but does not claim a provider received them; its state and attempts remain separate.

## Reproduce

```powershell
node --test apps/cli/test/source-recovery.test.ts apps/cli/test/source-discovery.test.ts
node --test apps/cli/test/memory-retrieval.test.ts apps/cli/test/search-projection.test.ts apps/cli/test/request-ledger.test.ts
npm run typecheck
node scripts/evidence-source-recovery.ts
npm run check
```

The evidence command validates the SHA-256 of `fixtures/t11-source-cases.json` (`13bfeb501644eb497d97914f3e508a7b7e21ef2b52b82ef5d5f34105dfb11e7e`), records the implementation commit/worktree, exact command and process start/end/exit/signal, Node/platform/SQLite, actual ack, unit/version and assembly identities, search/expand outcomes, negative scope/revocation observations, per-assertion results, stdout/stderr plus SQLite/archive sidecar digests, controlled cleanup, and focused test output under ignored `artifacts/t11-*/`. It also runs the [archive reconciliation evidence](t38-archive-reconciliation.md), independently validating real process death at reservation/write/fsync/readback/ack boundaries and publication with a pending projection job. The corresponding gap is cleared only when that nested receipt passes. It reports `pass` only when all runtime checks pass and no declared evidence gap remains; the remaining provider/Host and production evidence requirements keep this synthetic T11 slice at `evidence-gap`. Runtime or receipt-validation failures report `fail`. The CLI carrier is file-backed and the counting transport records one local synthetic send; this is not evidence for a real provider or for authenticated owner UI input.

CI runs the same command as `npm run evidence:source-recovery` on Windows, macOS and Linux and uploads each receipt in that job's `synthetic-<os>` artifact. Each receipt covers only the host that produced it.

## Evidence Boundary

The tested publication decision is a structured synthetic Host user-role event. Report/proposal storage and export use [AnalysisArtifacts](t13-capture-verification.md); the controlled [Agent window path](t18-context-windows.md) connects discovery and new-session continuation. Arbitrary interactive owner-channel authentication and external-provider behavior remain separate evidence requirements. No MC archive, real user files, production data or remote provider were accessed. The combined source/proposal projection and its new controlled copies need T20/T22a/T22b backup/purge coverage before live enablement. The disposable schema and search checks do not freeze the initial production schema or establish full-history coverage.
