## Window and request authority

`AgentRun.newWindow()` operates at a settled ReAct boundary. It verifies archived input, complete responses and tool results before recording a new window identity, predecessor and raw recovery references in the existing request-event log. It does not generate a summary or remove canonical history. Source loss prevents the window transition. A repaired exact source can be revalidated and used by a later transition.

Each Agent assembly freezes its window ID, cache-epoch ID and P0/P1/route/estimator digest. The owner-maintenance fence epoch, window, cache epoch, assembly and attempt remain separate identities. P2 appends and P3-only changes retain an unchanged prefix epoch. Fresh windows conservatively create a new cache epoch; this adapter does not claim a provider contract allowing reuse. Prefix changes invalidate the previous epoch durably before the replacement assembly. Missing or invalidated Agent context is rejected by the Store at assembly, admission, tool and send boundaries.

The baseline contains the current durable intent, exact active guidance, bounded operation state and a raw recovery anchor. A fresh window retains the latest complete assistant/tool batch and its associated inputs. All admitted steering inputs remain exact: inputs whose original P2 turns are offloaded move into the P1 baseline. Current input, goal, hard constraints, full active instructions and output reserve are never truncated. Window changes keep the same run, request ledger, cumulative model/tool/token usage and deadline. Terminal runs remain terminal. Explicit recovery or follow-up uses the existing separately authorized new-run protocol. After a completed task, a new run with a fresh owner steering input starts a new intent identity and exact source-backed goal on the same monotonically versioned event chain. It preserves the completed predecessor and its revoked grants. An active task keeps its existing goal; a model or tool result cannot supply the owner input for a new task.

Degradation uses the optional material available in this slice: first a bounded recent operation projection with an archive digest, then the newest complete operation result if further reduction is needed, then a fresh window at a complete ReAct boundary. Remaining mandatory overflow ends as `needs-input`; cumulative exhaustion ends as `budget-exhausted`. Ledger degradation records distinguish `compact`, `selected` and `window`. Zone sizes describe the neutral P0–P3 JSON; the final encoded transport byte count independently governs the actual context inequality.

## Exact instructions and source recovery

`AgentRun` consumes a Host-bound `GuidanceSession` and explicit resource targets. It revalidates sources/scope before assembly, admission, physical send and tool execution. A fresh window clears the file-body cache. Full AGENTS/Skill/reference bytes and their scope/hash metadata enter the protected local-guidance block. The selected Skill keeps its qualified source identity; changed or missing bytes cannot be replaced with a same-name Skill. Unavailable guidance durably invalidates the old epoch and blocks dispatch.

The HTTP adapter preserves historical P2 message bytes and puts the current intent/input in P3. P0 guidance and P1 baseline are separate fixed messages. Provider metadata cannot create guidance, register tools or grant authority.

The existing eight-tool schema now enables bounded `source.search`, `source.expand` and `memory.search` in `AgentRun`, plus `skill.search` when local guidance is bound. The pump executes these Core operations only after the complete model response is archived. They do not route through arbitrary Host effects. Session search checks authority before matching text, excludes unauthorized historical entries with an explicit coverage count, and preserves accessible local results; other source-integrity failures remain visible. Project search reuses the existing approved source/proposal projection. Unicode expansion limits, immutable versions and explicit source errors remain visible in paired tool results. A failed lookup can be followed by a normal model response.

Cross-project requests use only the grant supplied by the Host. Models cannot supply a grant, target environment or approval. The run and each cache epoch persist the selected grant. Store admission and send transactions revalidate it, and revocation invalidates affected epochs and request runs in the same transaction. Before any model/tool output reaches the archive, its event identity is durably bound to the grant; lost acknowledgements cannot leave an unprotected copy. Session recovery checks the original task grant and the current Host scope, including after restart. Read-only analysis does not enqueue automatic memory capture. An assembly freezes the record/revision/head/hash identities from its selected archived `memory.search` results in `usedMemories`, tagged `retrieved-memory`. Store checks reconcile these identities with the actual selected tool-result sources and revalidate current eligibility inside the assembly, started and send transactions. A stale or forgotten memory cannot be resent as active historical context. Cross-project results retain their original target labels, including `reference_only`; freezing their identity does not promote them or change canonical truth. A new session starts with its own local authority and cannot use another session's analysis grant.

## Settled operation history

`correctionModelSummaries()` still validates the complete canonical delivery history. `correctionModelContext()` selects whole recent summaries within a fraction of the request budget and always retains the newest complete summary. Older entries are represented by a count, omitted count, full collection digest and source-recovery query. No selected rollback member is truncated, and canonical revisions, full receipts, archived summaries and cancellation/supersession results remain intact.

Probe and Agent requests share this bounded projection, including after reopening the same session. A changed operation collection invalidates an already admitted but unsent Agent snapshot. Before using historical memory values, retrieval rechecks the current head and source eligibility. The projection itself neither restores a forgotten record nor verifies a corrected body.

## Reports and new-session continuation

The controlled scenario runs the actual `AgentRun` and pump through old-source recovery, memory discovery, approved project source discovery, exact expansion and an unavailable reference followed by a completed report. It stores the complete report using `AnalysisArtifacts`, publishes only the preapproved section, creates a second immutable version, publishes the approved ordinary handoff Markdown and removes its temporary file. The target project's independently created session expands both report versions and the archived handoff using its own current scope. No handoff Skill is required. A separately fixed synthetic owner decision stores the complete inert proposal; a subsequent model run searches, expands and assesses that saved proposal before the controlled self-contained Markdown export.

Frozen capability descriptions supply the synthetic evidence. Neither the source run nor the target session verifies a real repository or implements the proposal. The target result requires current-source review. Report, proposal and export bodies stay in their source-owner archive; receipt metadata contains references and hashes.

## Storage, checks and evidence limits

The disposable schema is version 21. `request_assemblies.context` stores the frozen context identity; window, epoch and source-access lifecycle events reuse `request_events`. A partial source-access index binds lookups to session/event identity without scanning unrelated request payloads. There is no migration path. Existing schema-version evidence checks use the same version. No new product carrier is introduced: source bodies use registered session JSONL, request facts use SQLite, and synthetic transport observations use `counting-receiver.jsonl`. Temporary guidance fixtures are owned and removed by the controlled command after the run; the archived immutable snapshots remain available for evidence inspection.

Focused tests cover pressure and explicit windows, exact guidance and steering retention, epoch stability, source loss and repair, grant revocation by a second Store, protected archived copies and lost acknowledgements, same-session local continuation after task completion and restart, memory qualification changes interleaved with started/send admission, preservation of already-sent receipts, stale memory, cancellation and late replies, cumulative limits, unavailable references and subsequent normal completion. A mixed sequence of repeated correct/forget/independently approved restore operations, supersession, cancellation and multi-member rollback validates bounded requests, full receipts and current truth across session restart. `context-http.test.ts` runs the complete prerequisite command before its accepted local HTTP scenario, independently matches seventeen transmitted payloads with ledger attempts, and checks actual instruction bytes and recovered evidence. The skip-expansion HTTP case fails before report publication. The rejected-preflight case uses the existing test-only subprocess fixture and sends zero requests.

`npm run evidence:context` retains the actual CLI stdout/stderr, copied SQLite/JSONL, fixture and artifact digests, implementation commit/dirty status, environment, command and exit result under `artifacts/t18-*/`. Its independent raw checker recomputes source/event/receiver/proposal hashes and checks window/epoch linkage, budgets, run terminals and handoff receipts. CI runs the synthetic command and complete tests on Windows, macOS and Linux; a local receipt proves only its recorded platform.

A local counting or HTTP fixture is not a real-provider behavioral verdict. Without an authorized external route and budget, actual-model long-session quality, instruction adherence and target-project continuation remain `evidence-gap`. Interactive owner authentication for arbitrary guidance directives/conflict resolutions, non-CLI hosts, Historian compartments (T19), backup/purge (T20–T22), full-schema acceptance (T24), production data and migration remain outside the demonstrated controlled path. Protected tool-output lost acknowledgements are covered here; process-crash and torn-source-append fault injection remains tracked by #38. These limits do not become passes when synthetic checks succeed.
